# Format specs — what each target type looks like as finished text

Read only the sections for the target types approved in Step 2. Every piece holds the core
message from Step 1 fixed and re-fits format, length, and norms. All output is text, ready to
paste. Nothing is designed, recorded, edited, scheduled, or posted.

---

## `linkedin` — LinkedIn post (text or image post)

- **Hook (line 1)** before the ~140-character "…more" cut: a VoC pain stated plainly, a sourced
  number, a contrarian claim, or an open loop. No warm-up.
- **Body:** 900–1,500 characters, one idea per line, blank line between beats. Built from one
  key point of the source, not a summary of all of them.
- **CTA:** a specific question or a comment-keyword CTA (`Comment "WORD" and I'll send you
  [lead magnet]`). Link, if any, goes in the first comment — say so.
- 0–3 niche hashtags at the very bottom. No markdown (LinkedIn renders it literally).
- If it is an image post, add one line: `Image idea: [the single idea the image shows]`.
- For the same post adapted to Instagram and X as well, use `/socialpost-writer`.

```
[Hook]

[Beat 1]

[Beat 2]

[Objection handled in one line]

[CTA]
#niche #niche2
```

## `thread` — X thread (or a LinkedIn multi-post)

- 5–10 numbered posts, each ≤280 characters and readable in isolation.
- Post 1 is a standalone hook that earns the thread. One idea per post. Payoff near the end.
- Last post: CTA. Link goes in a reply, not the main posts. Max 1–2 hashtags in the whole thread.

```
1/ [Standalone hook]
2/ [One idea]
…
N/ [Payoff + CTA]
[reply] [link + what they get]
```

## `newsletter` — newsletter issue or section

- **Subject line** 40–60 characters, curiosity or value, not clickbait. Give 2 options.
- **Preview text** 40–90 characters that complements (does not repeat) the subject.
- **Body:** TL;DR (1–2 sentences) → 2–3 takeaways, each a short paragraph with its sourced
  stat or example → one personal line (the information gain from the source) → one CTA.
- As a **section** inside an existing newsletter: drop subject/preview, keep a section heading,
  150–300 words, one CTA or link back to the source.

## `email` — standalone email (nurture or announcement)

- Subject (≤50 characters) + preview text.
- Plain-text feel: short greeting, 3–6 short paragraphs, one idea, one CTA link, sign-off from
  a real person. 120–250 words.
- Written to one reader ("you"), in the buyer's words from `voice-of-customer.md`.
- No images required; no tracking or sending instructions.

## `shortform` — short-video script (Reels, TikTok, Shorts — one script serves all)

- One idea only, 30–60 seconds (~75–150 spoken words). Note the estimated duration.
- Structure: **Hook (0–3 s)** → **Setup (3–10 s)** → **Payoff (the one insight)** → **CTA**
  (comment-keyword → DM → lead magnet works well).
- Two columns or labeled lines: what is said, and `[ON SCREEN: …]` / `[B-ROLL: …]` cues.
- Vertical 9:16 framing note. Captions text = the spoken lines.

```
HOOK (0–3s): "[line]"            [ON SCREEN: 3–5 word text hook]
SETUP (3–10s): "[line]"           [B-ROLL: …]
PAYOFF: "[line]" "[line]"         [ON SCREEN: key number + source]
CTA: "[line]"                     [ON SCREEN: keyword]
Estimated duration: ~[N] s
```

## `longform-video` — YouTube-style script outline

- Hook (0–15 s) → promise / why watch → 3–5 talking points from the source's sections, each with
  a visual cue (`[SHOW CHART]`, `[B-ROLL]`, `[TEXT ON SCREEN]`) → recap → CTA.
- ~150 spoken words per minute; note the estimated duration.
- Only from a rich source (long blog, transcript). A thin source is flagged, not padded.

## `carousel` — carousel slide text (LinkedIn / Instagram)

- 6–10 slides. Slide 1 = hook (max ~10 words + optional sub-line). Slides 2–N = one point each
  (headline ≤8 words + 1–2 short supporting lines). Final slide = CTA.
- Text-light: if a slide needs more than ~30 words, split it.
- Deliver as `Slide 1: … / Slide 2: …` plus a short caption (hook line + 2–4 lines + CTA).
- Add a one-line `Visual idea:` per slide only where a chart or diagram carries the point.

## `blog` — blog article

- Repurposing *up* into a blog (e.g. from a transcript or a thread): for a full SEO article with
  research, outline approval, and fact-checking, hand the extracted core to `/blog-write`.
- If the user wants a quick version here: answer-first opening, scannable H2s, Key Takeaways box,
  the source's sourced stats, a short FAQ, one CTA. Add the information gain the source had.
